# Four-Quantum-Dot POD-NN: 49×49 / 40 States / 80 Modes

**Self-contained, CPU-only** research demonstration comparing a global POD neural
network with automatically clustered local experts and POD-Galerkin on held-out
randomized four-quantum-dot geometries. All data are generated by this repo;
no previous MATLAB files, trained weights, or quantum-dot libraries are needed.

**This release has been updated for stronger tanh training and expanded plotting.**
The original KMeans *selection objective and numerical settings* from the
40-state/80-mode Lasso-sparse research experiment remain unchanged.

> Results are measured, not forced. The targets (local wave error <0.20,
> energy error <0.02, local/global online time ≤1.20) are evaluation criteria,
> **not demonstrated outcomes** of this release. A tiny integration run validates
> the software but cannot verify accuracy after a full training schedule.

## Default experiment

| Setting | Default |
|---|---|
| Spatial grid | 49 × 49, periodic 16 nm × 16 nm square |
| DNS eigenstates per geometry | 40 |
| POD modes | 80, computed from training geometries only |
| Geometries | 4 options per dot × 4 dots = **256** |
| Train / validation / test | 70% / 15% / 15%, split by **geometry** |
| NN activation | **tanh** for global and all local models |
| Hidden layers | 4 |
| Global hidden width | 160 |
| Local widths | 96 / 128 / 160 / 192 by cluster size |
| Batch size | 128 |
| Stage 1: coefficient training | **up to 850 epochs** |
| Stage 2: density / wave reconstruction | **up to 200 epochs** |
| LR schedule | Cosine annealing per stage |
| Validation | Every 10 epochs; best checkpoint restoration and patience stopping |
| Clustering | Original Lasso-sparse modal-energy signature KMeans with K = 2…8 |
| Online inference | Automatic packed/sequential expert benchmark and 1/2-thread CPU selection |

This preset is **much more CPU-intensive** than the old 81-geometry / 160+40
preset. On ordinary desktop CPUs, expect substantial training time. The
full research preset retains q=6, 1,296 geometries and 3,500+700 epochs,
but those are not the default.

## Install on Windows (PowerShell)

Extract the ZIP, then open PowerShell in the **inner folder containing
`main.py`, `requirements.txt`, `configs`, and `src`**. For example:

```powershell
cd "$env:USERPROFILE\Desktop\quantum-dot-pod-nn-tanh-40state\quantum-dot-pod-nn"
```

If the path differs, use File Explorer to open the actual folder containing
`main.py` and choose **Open in Terminal**.

**Option A: reuse your previously installed virtual environment** (no new
installation of Python required):

```powershell
$python = "$env:USERPROFILE\Desktop\quantum-dot-pod-nn-repository\.venv\Scripts\python.exe"
& $python -m pip install -r requirements.txt
& $python main.py
```

**Option B: create a new environment** (the cleanest approach for GitHub
reproducibility):

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install torch --index-url https://download.pytorch.org/whl/cpu
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

Run the tiny smoke test first if you want to verify installation:

```powershell
& $python main.py --config configs\smoke_test.yaml
```

You may also run `py -3.12 main.py` without a virtual environment if the
required packages are installed globally. No venv activation is necessary.

## How the model has been strengthened

1. **More independent geometries**: 256 instead of 81, with the original
   four-dot randomization ranges (centers ±0.75 nm; radii 1.35–1.65 nm;
   depths 2.0–2.4 eV). The entire geometry is held out for validation/test.
2. **850+200 maximum epochs** with tanh, cosine LR scheduling and smaller
   minibatches than the original 256-batch simplified run.
3. **Wider MLPs**, while keeping the *original* cluster-assignment procedure.
   The total local parameter count is disclosed in `parameter_counts.csv`.
4. **Train-only POD sign anchors**: real eigenvectors have arbitrary global
   sign. Each state obtains its most prominent POD-coordinate anchor using
   training geometries only. Coefficient/wave labels are consistently
   oriented, and an optional gauge-aware supervised loss is added to the
   existing sign-invariant and physics-informed losses. The gauge selection
   does not depend on test geometries.
5. **Better validation control**: model selection uses actual sign-invariant
   full-space wave L2 on validation geometries. The best checkpoint is
   maintained **across both training stages**, so stage 2 cannot overwrite a
   superior stage-1 checkpoint. Early stopping is available when progress
   stalls.

These changes are meant to improve generalization but do **not** guarantee
that either NN reaches a particular error. Near-degenerate eigenstates can
rotate within their eigenspaces even after sign anchoring. For publication,
consider eigen-*subspace* errors and convergence against finer-grid DNS.

## Original Lasso/KMeans local clustering retained

- For each state and POD mode, soft-threshold coefficients by `alpha=0.0001`,
  square, average across the training geometries, and normalize each state
  signature to sum to one.
- Fit `KMeans(n_clusters=K, random_state=42, n_init=30)` for K=2,…,8.
- Score the original validation modal-energy compactness, state-count penalty
  (soft minimum 1; max target 18) and size imbalance with weights 0.08,
  0.02, and 0.005.
- Remap expert IDs by ascending mean eigenstate index. State-to-expert routing
  is fixed before testing. **No latency-aware KMeans penalty was added**.

See [`docs/clustering_provenance.md`](docs/clustering_provenance.md) for the
exact original objective and source mapping. The strengthened local widths
change capacity, **not cluster selection rules**.

By default, physical-domain reconstruction panels are generated for **two
fixed held-out geometries**, for states **1, 10, 20, and 40**. Those choices
are specified in YAML before evaluation, not chosen to favor the local NN.
Wavefunction signs are aligned to DNS only *for plotting*, because overall
sign does not change the physical wavefunction or density.

### Important metrics

- `metrics/summary.csv`: mean sign-invariant relative wave L2, density L2,
  energy error for all three prediction methods.
- `metrics/per_state_errors.csv`: individual geometry/state errors.
- `metrics/timings.csv`: **each test geometry, each method**, with timing
  breakdown; CSV can generate your own figures.
- `metrics/goal_check.csv`: reports whether local L2 <0.20, local energy <0.02,
  local/global full online latency ≤1.20, and local wave L2 < global wave L2.
  These checks do **not** influence training or model selection.
- `metrics/training_history.csv`: weighted training losses **and separate**
  validation wave L2/energy errors. A weighted objective of 1e-1 is not a
  10% relative wavefunction error.
- `metrics/gauge_anchor_modes.csv`: the train-only sign reference for each
  eigenstate and sign-flip counts.
- `metrics/cluster_validation_scores.csv`, `expert_state_groups.csv`,
  `parameter_counts.csv`, `cpu_inference_tuning.csv`: clustering and compute
  audit trails.
- `run_summary.json`: selected K, geometry counts, performance, goal checks,
  backend and thread count.

**Timing convention:** NN total online times include reduced-operator feature
construction, NN forward inference, and reconstruction. POD-Galerkin includes
its own reduced operator, eigensolve, and reconstruction. DNS is labeled
**solve-only**, not end-to-end setup/training. All are measured on the CPU.
The one-time POD basis construction and neural training are offline expenses.

## Scientific limitations

- **Coarse-grid physics**: 49×49 may not resolve all 40 high-energy states;
  check eigenvalues and eigenfunctions against finer grids before publication.
- **Near degeneracy**: A real eigenvector's sign can be fixed; a degenerate
  eigenspace's rotation cannot be fixed by sign alone. Consider subspace
  projectors or matching states by overlap if needed.
- **Generalization**: Fitting data harder does not imply accuracy on new
  geometries. Use validation curves, different random seeds, and held-out
  geometry families.
- **Comparative capacity**: The combined local experts can have substantially
  more weights than the global model. Interpret a local win accordingly.
- **Run-to-run timing**: CPU thread scheduling and model packing vary; report
  your hardware and use repeated measurements.
